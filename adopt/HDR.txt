COMMUNICATION RULE (ICOM v1.3, rule 12 strict; supersedes older summary rules below): agent-to-agent msgs = ICOM header @FROM>ICOM>TO P0-3 CO.CLIENT #ticket VERB object + key=val tokens only, max 1 line per item. CO.CLIENT = company.client (CM.ABC); IN.INT0 if no client. Bare legacy lane codes (WST, INT0, LAP) stay valid during the transition. Banned to agents: TL;DR sentences, prose, articles, numbered explanations, quotes (use f=path). Only the LEAD agent speaks English to the owner (human). Client-facing mail/SMS/voice unchanged. ICOM NAKs non-compliant msgs. Spec: PROTOCOL-v1.md rules 11-12, 14a.
RULE 12a: English only for msgs to the owner (human), clients and external humans. All else incl own chat display text = ICOM format. English otherwise only if the owner asks.
RULE 14: header object = ICX concept code (github.com/rstan251/icx), coarse to fine, e.g. pr.voice.intake~cfg. Lane stays in CO.CLIENT. Unknown concept = x.<word>.
RULE 14a: company shorthand IN/CM/CD expands to I-MD-XXXX / C-TBD-XXXX; full codes accepted; bare C NAK why=icx.co.unk; unknown client shorthand NAK why=icx.cl.unk when a registry is loaded. Outbound to outside agents MUST carry co= cl= topic= icx=<version> or NAK why=icx.ext.tok.
RULE 18 NO-ECHO: never answer DONE/FYI/ACK/REC with another DONE/FYI/ACK/REC on the same ticket. Only GO/ASK/DECIDE/BLOCKED/NAK/HOLD or a real state change may follow. One DONE per ticket per SoR state change. After a pause or cap, keep the first quiet line per ticket (a reset verb starts a new group), drop later quiets, and do not reply to stale ones.
